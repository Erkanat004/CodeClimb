# SQLite и PostgreSQL

Локальный запуск: `npm run local`. Отдельный сервер БД не нужен; Node.js 24 использует встроенный `node:sqlite`. Первая загрузка создаёт `data/code-climb.sqlite` и применяет `server/migrations/*.sql`. Не храните рабочую БД на синхронизируемой сетевой папке при нескольких одновременных машинах. Для этого проекта в OneDrive можно перенести БД вне OneDrive через `SQLITE_PATH`.

Настройки процесса: `DB_DRIVER=sqlite`, `SQLITE_PATH=<абсолютный путь>`. Если `DB_DRIVER` не задан, после переноса через админку приложение использует зашифрованную сохранённую конфигурацию PostgreSQL. Для прямого выбора PostgreSQL задайте `DB_DRIVER=postgres` и `DATABASE_URL`. База содержит пользователей, хеши паролей, хеши сессий, раздельный прогресс Python/C++, версии схемы и лимиты входа.

Сделать согласованную резервную копию при работающем сервере: `npm run db:backup`. Копия появляется в `data/backups/`. Не копируйте только `.sqlite` вручную при открытом WAL. Для восстановления остановите приложение и сохраните старую БД вместе с `-wal`/`-shm` отдельно, затем восстановите согласованную копию. Никогда не публикуйте БД и резервные копии.

## Контракт хранилища

HTTP-обработчики используют только `server/repository.mjs`. SQLite SQL находится в `server/sqlite-repository.mjs`, PostgreSQL SQL — в `server/postgres-repository.mjs` и `server/postgres-features.mjs`. PostgreSQL-миграции отделены в `server/pg-migrations/`.

Асинхронные методы: `findUser`, `findEmail`, `createUser`, `bootstrapAdmin`, `createPending`, `getPending`, `deletePending`, `rotateCode`, `verifyRegistration`, `createSession`, `getSession`, `deleteSession`, `cleanup`, `rateLimit`, `getProgress`, `saveProgress`, `adminOverview`, `adminUsers`, `adminProgress`, `adminAction`, `close`. `createUser` используется для прежних аккаунтов/тестов; публичная регистрация проходит через одноразовый код.

`saveProgress` атомарно сравнивает revision и возвращает новую либо null при конфликте. Классический маршрут хранится в `progress`, отдельные сложности — `course_progress`, все 15 уровней — `full_progress`. Старые записи не перезаписываются.

`verifyRegistration` атомарно проверяет HMAC/срок/лимит, увеличивает счётчик ошибочных попыток либо создаёт игрока и удаляет ожидающую регистрацию. `rotateCode` использует compare-and-swap предыдущего хеша. `rateLimit` атомарно увеличивает счётчик. Блокировка и отзыв сессий пишут `admin_audit` в той же транзакции; смена хеша администратора отзывает его сессии. Эти гарантии должны сохраняться в PostgreSQL.

## Перенос через админку

1. Сделайте согласованную резервную копию SQLite (`npm run db:backup`) и храните её вне сервера. Завершите активные дуэли.
2. Создайте пустую PostgreSQL. На API задайте `DB_CONFIG_KEY` из не менее 32 случайных символов. Для встроенного контейнера укажите сильный `POSTGRES_PASSWORD` и дополнительный файл `compose.postgres.yaml`.
3. В админке откройте раздел «База данных», проверьте URL, затем подтвердите `MIGRATE`. На время миграции игра недоступна.
4. Сервер создаст согласованный снимок SQLite, перенесёт постоянные таблицы в одной PostgreSQL-транзакции и сравнит число строк. Сессии, временные коды и лимиты запросов не переносятся; после переключения войдите заново.
5. После успеха перезапустите API. Без явного `DB_DRIVER` он прочитает зашифрованный URL из `data/database-config.json` (AES-256-GCM). Неверный `DB_CONFIG_KEY` вызовет ошибку запуска, а не скрытый возврат на SQLite.

Если ошибка случилась до фиксации переноса, SQLite снова принимает запросы. Если данные уже перенесены, но сохранить настройку переключения не удалось, запись остаётся остановленной, чтобы базы не разошлись. Сохраните обе БД и перезапустите API для возврата к SQLite. Не повторяйте перенос в частично заполненную PostgreSQL.

Для публичного удалённого PostgreSQL URL требуется `sslmode=verify-full`. Локальный Compose-сервис `postgres` доступен только в сети контейнеров и не публикует порт. URL в админке для него: `postgresql://codeclimb:<пароль>@postgres:5432/codeclimb`; специальные символы пароля нужно URL-кодировать. Старую SQLite не удаляйте до проверки входа, прогресса и восстановления резервной копии.

`npm run test:postgres` проверяет схему и контракт на PGlite, включая регистрацию, прогресс, награды, дуэли и перенос. Это не заменяет проверку на реальном PostgreSQL с конкурентными запросами.
