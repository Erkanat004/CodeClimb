## Известные ограничения

1. Отдельный Docker-judge не был испытан на этой машине: Docker/runsc недоступны. Поэтому изоляция пользовательского кода в реальном интернет-развёртывании должна пройти отдельное испытание на сервере. Пока judge не подключён, соревнования недоступны.
2. Реальная отправка писем и рекламный callback не проверялись без учётных данных и настроенного домена. Есть серверные адаптеры и тесты; до настройки этих сервисов их нельзя считать работающими в сети.
3. Полный `npm audit` показывает 15 предупреждений в инструментах разработки (8 high, 7 moderate; включая `braces`, старый `esbuild` внутри `drizzle-kit` и `fflate` внутри Vinext). Для части нет безопасного автоматического исправления без несовместимых замен. Не выставляйте dev-сервер в интернет; отслеживайте обновления зависимостей. Это не отменяет нулевой результат проверки рабочих зависимостей.
4. Отключение вставки в браузере — правило интерфейса, а не абсолютная защита от нечестной игры. Результат соревнования должен определяться только серверным judge и скрытыми тестами.
5. Гостевой прогресс хранится на устройстве и автоматически не переносится в аккаунт. Восстановление забытого пароля по email пока не реализовано.
6. Исходный код на GitHub и публикация работающей игры — разные действия. После загрузки репозитория инфраструктуру сети, домен, HTTPS, постоянное хранилище и внешние сервисы нужно настроить отдельно.

## Перед публичным запуском

Проверить настройки из [DEPLOYMENT.md](DEPLOYMENT.md) и [SECURITY.md](SECURITY.md), задать собственный пароль администратора и стабильные секреты вне Git, подключить настоящую почту, развернуть Docker-judge и испытать его изоляцию, включить HTTPS и резервное копирование SQLite. После публикации дождаться зелёного GitHub Actions и провести сквозной тест двух игроков в браузерах на разных устройствах.
