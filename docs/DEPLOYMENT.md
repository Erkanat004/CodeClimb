# Запуск CODE CLIMB в интернете

Подготовлена схема одного Linux-сервера: Caddy (HTTPS) → веб-приложение Next.js и отдельный Node.js API → SQLite в постоянном томе. Это инструкция и конфигурация для развёртывания, не сообщение об уже опубликованном сайте. Старый адрес Sites сам не обновляется.

## Что потребуется

- Linux-сервер с Docker Engine и Compose, домен с DNS A/AAAA на этот сервер.
- Свободные порты 80/443; наружу не открывать 3000/3001.
- Учётная запись Resend, подтверждённый домен отправителя и ключ с правом отправки писем.
- Для режима соревнования: отдельный приватный judge-сервис на Linux с Docker и `runsc`. Инструкция: [`judge/README.md`](../judge/README.md).
- Для подсказок за рекламу: аккаунт AppLixir, одобренный домен, строки `ads.txt` и серверный webhook secret.
- Резервные копии вне сервера, регулярные обновления ОС, Node.js, Caddy и зависимостей.

Используется [официальный API Resend](https://resend.com/docs/api-reference/emails/send-email). Ключ вводится только в приватный файл окружения сервера. Подключать Gmail/почтовый ящик к игре не нужно. Подтверждение домена и доставку на реальные адреса нужно проверить отдельно.

## Настройка

1. Перенеси исходники на сервер без `.env.local`, `data/`, `node_modules/` и старых сборок. Не удаляй локальную SQLite: это твои аккаунты.
2. Создай приватный файл `.env.production` по образцу `.env.example`. Он исключён из Git и Docker-контекста. Ограничь доступ к нему владельцем сервера.
3. Заполни значения:

```dotenv
DOMAIN=climb.example.com
ADMIN_USERNAME=Admin996
ADMIN_PASSWORD_HASH=сюда_полный_scrypt_v1_хеш
OTP_SECRET=отдельная_случайная_строка_не_короче_32_символов
PROXY_TOKEN=другая_случайная_строка_не_короче_32_символов
RESEND_API_KEY=секретный_ключ_Resend
MAIL_FROM=CODE CLIMB <verify@ваш-подтвержденный-домен>
JUDGE_URL=https://judge-private.example.com
JUDGE_TOKEN=секрет_длины_32_или_больше
APPLIXIR_WEBHOOK_SECRET=секрет_длины_32_или_больше
```

Это примеры, не готовые секреты. Для запуска без соревнований и рекламы `JUDGE_URL`, `JUDGE_TOKEN` и `APPLIXIR_WEBHOOK_SECRET` можно оставить пустыми; соответствующие функции будут выключены. Удалённый judge требует HTTPS с проверяемым сертификатом. HTTP допускается только через `localhost`/`127.0.0.1`, например через локальный туннель. Случайные секреты получи отдельными запусками:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
npm run admin:hash
```

`admin:hash` скрывает ввод пароля и печатает только хеш для настройки. Для нового экземпляра задай собственный уникальный длинный пароль администратора: пароль из переписки нельзя использовать публично.

При изменении `ADMIN_PASSWORD_HASH` и перезапуске API пароль существующего администратора обновится, его старые сессии завершатся. Обычный аккаунт с совпавшим именем никогда не повышается до администратора автоматически. Не меняй имя администратора без необходимости: другое имя создаёт отдельного администратора.

## Сборка и запуск

```sh
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production ps
```

Compose самостоятельно задаёт публичный режим, HTTPS origin и Resend. API откажется запускаться с недостающими настройками. Caddy принимает публичный трафик, заменяет доверенные заголовки и передаёт адрес клиента. Не выставляй API в интернет напрямую и не добавляй недоверенный proxy перед Caddy без отдельной настройки.

Открой `https://ваш-домен/` и `https://ваш-домен/admin`. Проверь: письмо приходит, неверный/повторный код отвергается, игрок не получает данные админки, код Python/C++ выполняется, прогресс сохраняется после перезапуска. Проверь на реальном домене сертификат и cookie Secure/HttpOnly. Не включай публичный трафик, пока эти проверки не пройдены.

Для соревнований отдельно проверь `https://ваш-домен/compete`: без judge кнопка создания должна быть выключена, с judge два аккаунта должны стартовать одну дуэль, а уровень должен засчитываться только после серверного verdict. Для рекламы сначала заполни раздел «Реклама и подсказки» в админке, проверь `/ads.txt`, затем сделай реальный тестовый просмотр на одобренном домене. Локальный fake-режим не даёт доход и не должен включаться публично.

## Данные и обновления

SQLite находится в именованном томе `account_data`. Пересборка контейнера том не удаляет. Не выполняй `docker compose down -v` — эта команда удаляет игровые данные и сертификаты.

Для согласованной копии работающей SQLite, затем копирования её на хост:

```sh
docker compose --env-file .env.production exec api node --input-type=module -e "import {DatabaseSync,backup} from 'node:sqlite';const db=new DatabaseSync('/data/code-climb.sqlite');await backup(db,'/data/backup.sqlite');db.close()"
docker compose --env-file .env.production cp api:/data/backup.sqlite ./code-climb-backup.sqlite
```

Перенеси копию в защищённое хранилище вне сервера; имя `backup.sqlite` внутри тома перезаписывается при следующей копии. Регулярно проверяй восстановление на отдельном экземпляре. Перед обновлением схемы сделай backup. Для нескольких API-реплик или большого числа записей сначала реализуй PostgreSQL-адаптер: [контракт БД](DATABASE.md).

## Честные ограничения

- Тренировочный код исполняется только в браузерной песочнице, не на сервере. Дуэли требуют отдельный judge; без него соревнование не работает.
- Самостоятельное восстановление пароля игрока, MFA и централизованный мониторинг пока не реализованы.
- Production-сборка проверяется отдельно командой `npm run build:network`. Docker/Caddy, реальные DNS/TLS и доставка писем должны быть проверены на целевом сервере; локальная сборка их не подтверждает.
- Дополнительные меры и границы: [SECURITY.md](SECURITY.md). Способ самостоятельного запуска веб-части соответствует [документации Next.js](https://nextjs.org/docs/app/guides/self-hosting).
